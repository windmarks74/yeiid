## 1. 숫자가 말하는 것 (최근 28일)

```
노출 645 → 등록정보 방문 86 → 설치 클릭 63 → 설치 52 → 첫 실행 29 → 구매 2
         13.3%            73%           83%         56%          6.9%
```

판정 셋:

1. **등록정보는 이미 잘 판다.** 방문→클릭 73%, 90일 기준 전환 75%. 업계 평균(20~30%)의 두 배가 넘는다.
   여기에 더 투자할 게 없다. 9/2 ASO 재작업이 제 몫을 했다.
2. **병목은 맨 위로 올라갔다.** 노출 645 = 하루 23회다. 전환이 100%여도 월 645명이 천장이다.
3. **설치→첫 실행 56%는 이상하다.** 통상 80~90%다. 측정 창 지연(말일 설치가 아직 안 열림)일 수도,
   실제 이탈일 수도 있다. → §7 진단 항목.

## 3. 왜 Play 스토어 검색만으로는 천장이 있는가

수요가 발생하는 순간, 사람들이 실제로 치는 검색어는 이렇다:

- "큐넷 사진 규격" · "큐넷 사진 용량 초과"
- "공무원 원서 사진 크기" · "공무원 증명사진 몇 픽셀"
- "토익 사진 규격" · "토익 접수 사진 안 올라감"
- "여권 사진 규격 몇 mm" · "여권 사진 반려"

**이건 앱을 찾는 검색이 아니라 답을 찾는 검색이다.** Play 스토어에는 이 질문의 답이 없다.
네이버와 구글에 있다. 그리고 우리는 방금 그 답을 올릴 자리(랜딩)를 만들었다.

### 결정적 근거 — 지금 그 자리에 있는 답이 틀렸다

9/2에 기관 공식 안내를 직접 대조하면서 발견한 것:

| 규격 | 검색에 도는 값 | 실제 공식 값 |
|---|---|---|
| 토익 | 115×150px · 500KB | 공식 px 규정 없음. 3×4cm · 머리 80~90% |
| 공무원 | 100KB | 137×177px · **350KB 미만** |
| KPC | 300×400px | 225×300px (상한 235×315) |

토익 값은 2016~18년 블로그가 출처였고, 공무원 100KB는 gosi.kr의 죽은 값이었다.

**상위 노출된 답이 낡았고, 우리는 공식 확인된 최신 값을 갖고 있다.**
이건 콘텐츠 경쟁에서 정면으로 이길 수 있는 자리다. 흔치 않다.

## 4. 핵심 전략 — 규격 사전(Spec Index)

랜딩을 **앱 소개 페이지가 아니라 답을 주는 사전**으로 확장한다.

```
yeiid.itbrown.com/
├── /qnet      큐넷 증명사진 규격 — 300×400px · JPG · 200KB 이하
├── /gosi      공무원 원서 사진 규격 — 137×177px · 350KB 미만
├── /toeic     토익 사진 규격 — 3×4cm · 머리 비율 80~90%
├── /kpc       ITQ·GTQ·SMAT 사진 규격 — 225×300px · 500KB 이하
├── /passport  여권 사진 규격 — 35×45mm · 200KB 이하
├── /us-visa   미국 비자·여권 사진 — 2×2인치 · 600×600px
└── /license   운전면허 사진 규격 — 35×45mm
```

### 각 페이지의 구성 (순서가 중요하다)

1. **답을 맨 위에.** 표 하나. 스크롤 없이 보이게. 검색해서 온 사람은 3초 안에 답을 원한다.
2. **출처 링크.** `q-net.or.kr`, `gongmuwon.gosi.kr` 등 — 앱 `usage.ts`의 `APPLY_URL`을 그대로 쓴다.
   출처를 밝히는 게 블로그와의 결정적 차이다.
3. **흔한 반려 사유 3가지.** 경쟁 앱 리뷰에서 반복되는 실패(용량 초과, 배경 얼룩, 머리 비율)를 쓴다.
4. **"폰으로 1분에 맞추기" → 설치 CTA.** 답을 준 다음에 판다. 순서를 뒤집으면 이탈한다.
5. **갱신일 명시.** 규격은 바뀐다. 날짜가 곧 신뢰이고, 낡은 블로그와 구별되는 지점이다.

### 왜 이게 최고 레버인가

- **₩0.** 손익분기 CPI가 ₩158인 상황에서 유일하게 산수가 맞는 채널
- **복리로 쌓인다.** 광고는 끄면 0이 되지만 색인된 페이지는 남는다
- **이미 가진 자산의 재사용.** 규격 데이터·출처·검증 과정이 전부 `usage.ts`와 `MAINTENANCE.md`에 있다
- **수요 발생 순간을 정확히 잡는다.** "규격이 뭐지?"는 사진을 만들기 **직전**이다
- **Play 검색이 닿지 못하는 트래픽**

### 전제조건 (먼저 해야 함)

- 구글 서치콘솔 · **네이버 서치어드바이저** 등록 + 소유 확인
- `robots.txt` + `sitemap.xml` (현재 랜딩에 없음)
- 각 페이지 canonical·og 태그

## 7. 실행 순서

### Phase A — 0~4주: 기준선과 전제조건

1. **1.2.3 효과 관측.** 저장 지연 수정·시험 규격 4종·인앱 리뷰가 전환에 준 영향. 새 기준선을 잡는다
2. **설치→첫 실행 56% 진단.** 측정 지연인지 실제 이탈인지. ANR·비정상 종료 지표 대조
3. `robots.txt`·`sitemap.xml` ✅ 배포 완료 (Cloudflare 관리형 robots.txt는 우리 파일을
   대체하지 않고 콘텐츠 시그널 주석만 앞에 덧붙인다 — `Sitemap:` 선언 살아 있음)
   ✅ **네이버 서치어드바이저 — 2026-09-13 등록 완료.**
   소유확인(HTML 태그, 랜딩 `<head>`에 상주 — 지우면 재확인 실패), 웹페이지 수집 5건 요청
   (`/` `/qnet` `/gosi` `/toeic` `/kpc`). 색인까지는 신규 사이트라 수일~2주 걸린다.
   ✅ **구글 서치콘솔 — 2026-09-13 등록 완료.**
   소유확인은 HTML 파일(`site/yeiid/googlea2c4527cfab17c57.html`). `sitemap.xml` 제출 성공,
   **발견된 페이지 6개**.

   > 배운 것 ①: Workers 정적 자산이 `.html` 을 확장자 없는 경로로 307 리다이렉트하는데도
   > **구글 소유확인은 통과했다** — 구글 검증기가 동일 호스트 리다이렉트를 따라간다.
   > 다만 이 확인은 리다이렉트에 의존하므로 `설정 > 소유권 인증`에 HTML 태그 방식을
   > 하나 더 걸어두는 게 안전하다(구글도 권고). 미완.
   >
   > 배운 것 ②: 네이버는 개별 페이지를 `요청 > 웹페이지 수집`에 넣지만,
   > **구글은 `URL 검사 > 색인 생성 요청`이다.** `Sitemaps` 에 개별 페이지 URL을 넣으면
   > "유형: 알 수 없음 / 오류"가 된다(실제로 4건 발생 → 삭제 대상). 순위 영향은 없다.
4. **평점 수 추적.** 14명 → 인앱 리뷰 요청이 몇 건을 만드는지. Play 순위 신호

### Phase C — 12주~: 관측과 조정

8. **네이버 블로그 — 2026-09-20 주에 시작 (2026-09-13 결정).**
   규격 사전 8종 내용을 블로그 글로 옮긴다. 한국에서 "큐넷 사진 규격"을 치면 상위가
   네이버 블로그라, 우리가 이기려는 그 자리다. 사이트 + 블로그로 유입 두 갈래.

   > 인스타/페북은 하지 않는다. 증명사진은 필요할 때만 찾는 저빈도 상품이라
   > 피드에서 발견되지 않고, 신규 계정은 도달이 0이다. §6 "하지 않을 것"과 같은 논리.
   > 자격증·취업 카페 글도 제외 — 대부분 홍보 글을 금지해 계정 정지 위험이 있다.
